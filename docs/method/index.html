Method · Spec v2.0.0 in plain terms

Method

Aletheia runs openness and rigor at full, in separate steps of one loop. First keep the rough idea alive and state the sound claim inside it. Then check that claim hard with code that shares nothing with the first check.

This page sums up the full spec. Where this page and the spec differ, the spec wins. Read the full spec on GitHub.

01//The loop

Five steps, then round again

One loop, five steps.

A raw draft, a number that looks too clean, a bug or a wall all count as a start. The loop turns that start into a claim with a stated scope, or into a clear reason it fails.

  1. Raw portal. Start from the raw source itself: a draft, a log, a transcript, a coincidence, a bug or a wall. Do not grade it yet.
  2. Keeper re-entry and steelman. The keeper stays in the loop and goes back into the raw source with each new surprise as a lens. Log every bug in full. Then state the strongest sound claim near the draft and test that claim.
  3. Probe. Run an exact proof or a live test in the domain. Say in advance what result would kill the claim.
  4. Tomography. Check from a second angle with no shared code. Change basis, units and precision. Run matched nulls. A catch comes with a small failing case and, where the core holds, the fix that lets it pass.
  5. Transfer. Move only exact operators to a peer front, with typed objects and a map that runs. Shared words alone carry no weight.

A wall is not the end of the loop. A sharp wall either is a theorem in its own right or names the missing term to add next. See how this ran in practice on the joint map.

02//Laws

Laws 1 to 5 plus Law 2b

Six rules that hold the loop together.

LawRule in one line
Law 1Keep the keeper active for the whole run and re-enter raw sources on every surprise, clash or wall.
Law 2Log each bug, then build and test the strongest sound claim beside the flawed draft before you close the line.
Law 2bBefore you mark a formula falsified, search the seven change families T1 to T7 under guards G1 to G4.
Law 3Check with no shared code across bases, precisions and nulls, plus contracts R1 to R7, and give a failing case with each catch.
Law 4Start every result at N0 and lift it only after full text search by mechanism in at least two nearby fields.
Law 5Allow a cross-field claim only with typed objects, an explicit map, an exact identity or a defect score that beats nulls, and a new prediction.

Read the laws in the spec

03//Gates

Gates 1 to 10

Sound first. New second. Fair last.

Gates 1 to 8 test if a claim is sound. Gate 9 tests if it is new. Gate 10 gives every cut or rejection a second hearing.

Soundness: gates 1 to 8

GateWhat it asks
Gate 1Replay from scratch at a pinned commit with logged seeds. Do not trust stored pass marks after edits.
Gate 2Hold fixed under change of basis, gauge, units, metric and mesh.
Gate 3Beat matched nulls and hard edge cases by a margin set in advance.
Gate 4Decide number claims in exact arithmetic or safe intervals, not by float cutoffs.
Gate 5Show typed objects, a map that runs, an exact identity or low defect score, and a new prediction for any bridge claim.
Gate 6Beat the plain baseline, rule out hard coded answers, and pass on fresh draws with no retuning.
Gate 7Pass contracts R1 to R7. The checker itself must earn trust.
Gate 8Hash plans before you see the data, latch fit checks before fitting, and keep every miss on record. A check that sits wholly inside the fit space stops as blind.

Novelty: gate 9

Gate 9 is mechanism first prior art. Restate the object and the mechanism in plain maths terms and in the words of at least two nearby fields that use the same mechanism. Search full texts under each restatement. Write down the restatements tried, the fields searched and the texts read. A match on mechanism sets the label, whatever words the source used.

Advocate: gate 10

Gate 10 is the second pass advocate. Each falsified or partial verdict, and each cut to a novelty label or claim scope, goes to a second checker who rebuilds the proof from scratch, reads the cited prior work in full and tests Law 2b changes. The ruling is stands, stands narrowed or falls, with the strongest claim that still holds. Before you publish a label above N0, ask an outside observer where you can.

04//Contracts

R1 to R7: rules for checkers

A checker must prove it can still say no.

The gate rule is plain: a verdict must not move with how the input is spelled, nor with values the sender merely declares. R1 to R5 are the floor. R6 and R7 close the gap where sender fields pick the rules or stand in for real counts.

ContractRuleHow it is held
R1 Default rejectEmpty, blank, null, missing field or unknown status inputs fail closed.Strict key checks that return reject or raise a set error.
R2 Omission ruleDeleting required proof fields must never turn reject into accept.Tests drop each required field in turn and confirm reject.
R3 Strict parsing, both waysAn accepted input respelled is rejected. A rejected input stays rejected when any well typed value is respelled, such as 0 or 1 for true, a trailing newline, duplicate keys or floats.One fixed spelling per value with strict types in both directions.
R4 Mode parityThe same verdict in python3 -I -B, python3 -I -O -B and python3 -I -B -W error, with zero bare asserts and zero skips under -O. A write run under -O must not emit a pass that a plain run rejects.aletheia audit-check compares exit code, output hash and skip count across all 3 modes.
R5 Mutation kill rateEach named guard has a must-fail control that kills single site deletions and edge shifts. A run that samples only k of n sites with 0 survivors reads NOT_SHOWN, never PASS.aletheia mutate over local and imported guards.
R6 Pinned checksThe gate owner fixes the check list, ranges and limits before the input exists. No sender field may pick or override them.Pure rational gate code fails closed on any sender rule override.
R7 Measured, not declaredEach value set against a pinned rule is recomputed from the bytes to be passed. Declared hashes, counts and flags are checked against that count and never stand in for it.The gate recomputes byte hashes and exact rational norms itself.

Declared record scope. The pure rational certifiers for R6 and R7, Own-Terms-First and Law 2b check that a supplied record is well formed and meets the stated sums. They do not by themselves prove that the runs, null suites or second tools behind the record took place. That proof needs clean room replay and byte level checks under R6 and R7.

05//Oracle honesty

Exact, sampled, anchor · N0, N1, N2

Say what kind of check you ran.

Truth and novelty are two claims, not one. Gates 1 to 8 cover truth and carry an oracle label. Gate 9 covers novelty. Every result starts at N0.

Oracle labelWhat backs itWhat you must not claim
exactFormal proof, symbolic identity, a certificate per input, or full finite enumeration.Exact arithmetic alone is not an exact oracle. Random draws in exact rationals stay sampled.
sampledFinite random, multi seed or grid checks, with fresh seeds after a fix.Truth for all inputs, or PASS from a cut short gate run.
anchorOutside domain data that tests the spec itself. A fail blames the spec.Do not feed anchor results back to tune the claim.
reference_replayLive match with an untouched upstream program.Do not treat upstream bugs as facts about the world.
Novelty labelMeaning
N0Known or repackaged. This is the default until full text search by mechanism proves a clear gap.
N1A concrete local step: a repair, a counterexample or a firm test based rejection.
N2A new theorem, a sharp new invariant, an exact block theorem, or a sound cross-field transfer that clears gates 1 to 10.

State the oracle label and the scope limits next to every result. A scope limit is a map pin for the next round, not small print.

06//Own-Terms-First and Law 2b

Test on own terms first, then compare

Let raw data speak first. Let old theorems speak second.

Own-Terms-First guards raw data work. Law 2b guards formula work. Each stops a fast close in one direction and a loose rescue in the other.

Own-Terms-First

Phase 1 tests a pattern on its own terms: a raw rerun, held out unseen data and a second tool. Phase 2 compares with known maths, in a separate step. Phase 1 needs at least 2 nets pre-pinned across at least 2 axes such as rate, scale, window or instrument, with held out and second tool checks both true. Limits stay firm: per net alpha at most 1/10 and total error rate at most 1/4, with the sum of per net limits inside the total.

The pattern must clear both plain shuffled nulls and spectrum keeping nulls by a set margin, and beat negative controls by the same margin. New symbols earn their place only by repeat runs and by calls on unseen data. A claim with no measurable definition goes back to its author with no definition invented for it. A model ladder check splits a true remainder from plain model miss in exact rationals.

Law 2b: transformational steelman

Before you close a theorem or formula as falsified, the literal claim must fail first. Then search all seven admissible change families. A rescue must pass in full on held out cases. A final falsified verdict needs a block that survives every family searched. An unsearched raw falsified verdict is rejected on sight.

FamilyChange to try
T1Gauge similarity: view the same operator in a like basis.
T2Affine or Bregman shift: allow a set shift in the right geometry.
T3Metric chart: restate in a sound chart or metric.
T4Spectral PSD shift: allow a positive semidefinite spectral shift.
T5Semiring tropical: restate in the tropical semiring.
T6Subspace projection: project to the subspace the claim needs.
T7Order domain residual: split the domain by order and state the residual.
GuardWhat it blocks
G1Empty rescues. A rescue must pass its target in full and clear null checks with set margins.
G2Tuning to the test set. Scope is fixed before holdout, with fewer free terms than held out constraints.
G3Quiet relabels. Any scope change is logged. Exact rescues carry zero residual gap. Bounded rescues carry a small stated gap.
G4Fast closes. A final falsified verdict needs all 7 of 7 families searched plus a block that survives them all.

07//Operator calculus

8 glyphs, honest labels

Short signs for steps that recur.

Eight exact steps came up again and again across fronts. Aletheia gives each step one sign and one program in exact rationals and integers, run by aletheia calculus.

GlyphPlain meaning
⧄Fiber elimination by Schur complement: solve out one block and keep the reduced operator.
⧅Singular kernel shadow: report the kernel of the eliminated block, its coupling and its rank.
⦷Holonomy differential: compare the reduced operator with and without a twist.
⟠Observer net equalizer: average over a group orbit or take the net invariant part.
⧇Gluing obstruction ratio: the harmonic share of a form, as an exact rational in 0 to 1.
⦺Inertia signature: count positive, zero and negative modes as (n+, n0, n-).
⩩Exact null equivalence: X and Y match if and only if X minus Y is zero. Floats are rejected.
⫩Refusal verified gate: pass the input and fail every mutant of it.

Honest label. Per AUDIT-084R, 7 of 8 glyphs are shorthands for standard operations: 6 plain shorthands plus the overloaded ⟠. Only ⫩, the mutation tested refusal gate, acts as a typed execution operator, with an N0 origin in mutation testing. The reported scan found 0 of 227,540 hits in a Lean 4 corpus. The scan script and corpus are not in this repo, so that figure is reported here, not reproduced.

08//Relapse patterns

CS-01 to CS-14

Old habits have names, so you can catch them.

Fourteen relapse patterns, CS-01 to CS-14, name the ways a run slides back to static review or loose praise. The first 12 run as checks in aletheia diagnose. The last 2 are held by gates 9 and 10 and the advocate prompt.

PYTHONPATH=. python3 -m aletheia diagnose /tmp/my-expedition
PatternSignFix
CS-01 Static map trapKeeper parks as done in round 1 and never re-enters sources.Keep the keeper active. Re-enter on each surprise or wall.
CS-02 Fast dismissalFalsified or N0 verdicts with no steelman or Law 2b search.Run Laws 2 and 2b before you close a line.
CS-03 Language smugglingBridge claims in prose with no typed map or defect score.Hold Gate 5: typed objects, a map, a score and a prediction.
CS-04 Proxy shadowA toy matrix or set is certified in place of the real target.Run against the real equations, data or live upstream code.
CS-05 Glass gateBare asserts, float cutoffs in exact checks, unseeded random draws or zero must-fail controls.Hold R1 to R7 with audit-check, mutate and gate-v2.
CS-06 Local closeThe team stops at a sharpness wall.State the wall as a theorem or spawn the branch it names.
CS-07 Status inflationMerged, machine checked or N2 claimed with no merge, log or search.Keep standing tags: draft, uncompiled source and default N0.
CS-08 Compute leakageArms are compared by round count with no fixed compute cap.Fix one cap and report format bound solves apart from open escapes.
CS-09 Truncation mirageA long run law is claimed from cut short runs.Test finite size cutoffs before you claim a long run law.
CS-10 Denominator collapseSparse sums are split by hit count, not by a fixed total.Divide sparse sums by the fixed global total.
CS-11 Unit and radix fragilityRaw unit weights or base 10 float grading set the verdict.Scale features first and grade exact maths over rationals.
CS-12 Trust boundary shadowHidden wrappers, loose JSON reads, newline weak patterns or unpinned tools.Use strict JSON, anchored patterns, strict ancestor checks and the safety scan.
CS-13 Citation trail searchPrior art search reads only cited papers or source words.Restate by mechanism in at least two nearby fields first.
CS-14 One sided verifierCuts and rejections stand on one pass.Send each cut to an advocate who rebuilds and rules.
