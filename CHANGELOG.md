# Changelog

All notable changes to `Foundation-0/aletheia` are documented in this file. Specification changes follow [`CONTRIBUTING.md`](CONTRIBUTING.md) (issue/audit reference, version bump, and regression tests).

## [Unreleased]

### Added
- **`aletheia audit-check`: novelty status for `VERIFIED` `N2` ledger rows (`--outside-rulings`, `--strict-novelty`).** The spec asks an `N2` label to survive Gates 1–10 (§2.3), but `audit-check` raised nothing on a `VERIFIED` `N2` row that listed `G9` or used a prior-art word. Each such row now gets a novelty status. It is `SECOND_PASS_RECORDED` when the gates cell lists `G10` or when an `outside_observer.rulings.v1` file passed with `--outside-rulings` names the row's audit id, and `NOT_SHOWN` otherwise. `NOT_SHOWN` is the warning `N2_NOVELTY_NOT_SHOWN`, or an error under `--strict-novelty`. `SECOND_PASS_RECORDED` says only that a second pass is on record; the check does not read what the ruling decided about the label, so it is no support for the `N2` label (a ruling may have moved the label down). Ids match exactly, so a ruling on `AUDIT-011R` does not cover the row `AUDIT-011`. A combined row such as `AUDIT-015R / 016R` is matched on its leading id, so a ruling on `AUDIT-016R` alone does not cover it; every id its first cell names (slash shorthand expanded, listed as `row_ids`) counts as in the ledger for `outside_ruling_ids_not_in_ledger`. The rulings file is read in the shape of cave-expedition `verification/outside/rulings.json`: a file whose `schema`, `areas`, area names, `audits` strings or finding rulings (`stands`, `stands_narrowed`, `falls`) are missing or malformed is refused, as is an `audits` entry that holds a second id without a comma (`AUDIT-002 AUDIT-003`); other keys are not read. `--outside-rulings` or `--strict-novelty` with no ledger to check is refused. The summary adds `verified_n2_rows`, `verified_n2_without_outside_ruling`, `n2_novelty_not_shown` and `outside_rulings_checked` (without a rulings file, `verified_n2_without_outside_ruling` counts every `VERIFIED` `N2` row). On cave-expedition at `9729839` the run stays `PASS`: without the rulings file all `11` `VERIFIED` `N2` rows are `NOT_SHOWN`; with `verification/outside/rulings.json` `2` remain (`AUDIT-011`, and `AUDIT-015R / 016R`, on which the file names only `AUDIT-016R`), and the one ruling id the ledger does not carry is `AUDIT-020R`. Ideas from cave-expedition (outside rulings beside internal labels) and project-asma (a status counts only as a complete documented state); regression tests in `tests/test_outside_rulings_novelty.py`.
- **`aletheia audit-check --pinned-manifest`: `STALE` versus `UNKNOWN` hash mismatches.** A `PINNED_FILE_SHA256_MISMATCH` could not tell a pin that describes an older version of the file from bytes that never existed there. Each mismatch now also gets an entry in the manifest report's `mismatches` list: `STALE` with the newest commit on `HEAD` at which the file held the pinned bytes, or `UNKNOWN`. The match is measured: for each commit on `HEAD` that touched the path (`git rev-list --full-history`, renames not followed), the blob bytes it holds at the path are hashed. Each entry's `history` says how much a miss shows: `complete` (a full clone with no promisor remote, at least one commit touched the path, and every listed blob was read), `partial` (a shallow or partial clone, git could not say which, or a listed blob could not be read; a miss does not show that the bytes never existed), `untracked` (no commit on `HEAD` touched the path, as for an untracked file or a directory inside an unrelated repository; no history of the bytes was searched) or `unavailable` (no git, no work tree, an unborn `HEAD`, or a git call failed or timed out). The search reads local objects only: it never fetches a missing object from a promisor remote (`GIT_NO_LAZY_FETCH`, and no transport allowed), reads the pinned path as a literal path rather than a pathspec, drops inherited repository variables such as `GIT_DIR` and `GIT_WORK_TREE`, hashes stored objects rather than `git replace` substitutes, and gives each git call a 60-second timeout. Both statuses still fail the manifest, and the error strings are unchanged. The summary adds `pinned_mismatch_stale_count` and `pinned_mismatch_unknown_count`. Idea from project-asma `tools/check_implementation_hashes.py` (`OK`/`STALE`/`UNKNOWN`); cave-expedition's outside audit records that "`check_007` pins hashes from before the probes were patched" (`verification/outside/OUTSIDE_AUDIT.md`, line 94 at `9729839`). Regression tests in `tests/test_pinned_manifest_history.py`.
- **Data rights, consent and disclosure rules (text only):** a new subsection in `domains/biology-and-life-sciences.md`, adapted from the public rule files of `Foundation-0/project-asma` (`AGENTS.md`, `docs/reproducibility-and-data.md`). It covers rights before opening a dataset, what may enter Git (raw files only when their terms allow redistribution and they hold no personal data; participant-level or restricted material never, and it is not sent to external AI services, agents included), no per-record hashes (`project-asma`'s single sorted-key SHA-256 is cited as a pattern, not a rule: that repository's owner has not yet confirmed adding it to its list of persisted items, and a small cohort's labels can be guessed from it), aggregate-only disclosure, a dated human authorization before live acquisition of participant data, patient-grouped splits, outreach drafted by agents but sent by an accountable human, and labelled synthetic inputs. These are human-governance rules; aletheia's tools do not enforce them. A matching anti-pattern says that a clearly labelled synthetic input used because rights or authorization are not in place is not a Substitution Shadow (`CS-04`). `spec/proposals/EMPIRICAL_CLAIMS.md` gate 3 now says that pinning raw data by hash does not mean committing the bytes, and `prompts/peer-weaver.md` archives raw fetches only when their terms allow redistribution and they hold no personal data. `spec/LAWS_AND_GATES.md` is unchanged.
- **`evidence/EXTERNAL_EVIDENCE.md` and `tests/test_external_evidence.py`:** an index of where each sibling-repo script or record cited as evidence lives, with status (`main`, `PR-only`, `not on main at 9729839`), revision read and one sha256 per single-file artifact, after cave-expedition's revision table (`verification/outside/README.md:18-28`). The test fails if a `check_NNN` script cited in `README.md`, `THEORY.md`, `CHANGELOG.md`, `spec/`, `domains/`, `evidence/` or `docs/` has no row, or if a line calls a script that is not on cave main archived. It reads only this repository; `aletheia twin-check` already guards audit ids and the check-script count but not individual `check_NNN` citations. The test has must-fail controls on synthetic text.
- **Law-5 bridge checklist (`domains/README.md` §2):** a fifth check, discriminating power: the bridge criterion is run on a seeded panel of matched unrelated systems, with scrambled-partition versions, and their pass rate must stay below a margin declared before the run. Worked example: cave-expedition's Gate-5 predicate test (`verification/outside/gate5-unification/predicate/`), where every Hermitian or quadratic Schur predicate passed in 100 percent of applicable unrelated systems in two seeded panels of 360. The spec's Gate 5 already asks for an identity "beating nulls"; this is the operational check in the domain-pack checklist, not a spec change.

- **`aletheia mutate` null-mutant control (`aletheia/mutator.py`).** Every mutant is written back through `ast.unparse`, which changes the target's bytes before any guard is touched, and any non-zero exit of the test command counted as a kill. A `--test-cmd` that only pins the target's bytes, such as a sha256 check, therefore killed every mutant, and the run reported `PASS` at 100% without exercising a guard. If that run fails, `mutate` stops with `NULL_MUTANT_KILLED` (exit `2`); if it times out, with `NULL_MUTANT_TIMEOUT`. The message asks the user to remove byte or format pins on the target from `--test-cmd`. A passing run reports `"null_mutant": "passed"` in its JSON payload. The cost is one extra test-command run per suite. Regression test: `tests/test_aletheia_cli.py::test_39_mutator_null_mutant_control_refuses_byte_pin_kills`. The change was motivated by cave-expedition's outside mutation harness (`verification/outside/checks/twoloop_stack/mutate_stack_guards.py`). ## [2.1.0] — 2026-11-22

Twin-coherence release. The method repo and the Cave Expedition ledger now machine-check the claims they make about each other, and the audit of 2026-11-22 (`aletheia#13`) closed its fail-open and label findings.

### Added
- **`aletheia twin-check` (`aletheia/twin_check.py`, contract `spec/twin_contract.json`):** machine-checks the claims the aletheia and cave-expedition repos make about each other. Nine checks cover the audit id range in the cave ledger, the audit ids aletheia cites, the number of check scripts each side counts, the set of results labelled `N2`, the seam and portal counts, the cave README claim that every track reached `VERIFIED`, the byte identity of the two `LICENSE` files, and the CI in each repo. Each check reports `OK`, `DRIFT`, `PENDING` or `SKIP` with the file and line it used, and a `PENDING` entry names the pull request that clears it. `DRIFT` exits `1`, `PENDING` and `SKIP` exit `0`, and a missing twin repo is `SKIP`, so a repo's own CI never fails because a sibling repo was not checked out. The contract pins every count, so a number that changes in one repo needs a reviewed edit in the other.
- **CI job `twin-coherence`:** checks out `Foundation-0/cave-expedition` next to this repo and runs `twin-check` on every push and pull request.

### Fixed
- **`aletheia audit-check` (`aletheia#13`, "Audit scan fails open"):** the file walk now fails closed. A scan root that is not a regular file or directory is refused with the coded error `TARGET_NOT_REGULAR`; every entry is classified with `os.lstat` before anything is read; symlinks are never followed; new codes `SYMLINK_DIR`, `SYMLINK_OUTSIDE_ROOT`, `BROKEN_SYMLINK`, `NON_REGULAR_FILE` and `UNREADABLE_FILE` fail the run; files are opened with `O_NONBLOCK` so a path swapped for a FIFO cannot block the scan. `--allow-symlinks` downgrades the three symlink codes, and the default is fail closed.
- **Strict JSON (`aletheia#13`):** a float literal that silently underflows to zero, such as `1e-999`, is now refused with `JSON_FLOAT_UNDERFLOW`, so a value cannot disappear into `0.0` without a trace.

### Changed
- **Novelty labels (`aletheia#13`, "Flat VERIFIED N2 wording"):** every label in the domain packs, the case study and the worked example now matches the outside two-pass check of the Cave Expedition ledger, which lowered several results from `N2` to `N1` or `N0` because the same mechanism exists under another name in a neighbouring field. Each changed label carries a pointer to the ruling.

### Changed
